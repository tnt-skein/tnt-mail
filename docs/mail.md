# Почта: отправка и чтение

`tnt-mail` — почта для Tarantool: письмо уходит по SMTP, а забирается
по POP3 или IMAP. Письмо собирается и разбирается целиком, шифрование
поднимается поверх сокета, а отказ — пара, а не исключение.

```lua
local mail = require('tnt.mail')

mail.configure({ from = 'tarantool@example.org', smtp = { host = '127.0.0.1', port = 1025 } })
local ok, err = mail.send({ to = 'duty@example.org', subject = 'Реплика отстала', text = 'Подробности' })
```

Вход с паролем без шифрования запрещён, пока его не разрешили явно,
а каждая операция с сервером ждёт не дольше своего срока.

Письма приложения — «подтвердите почту», «вам ответили» — объявляются
один раз: тема, получатели, вид на шаблонах и данные. Из одного вида
собираются обе части письма, уходит оно очередью с повторами, а посмотреть
его можно в браузере, ничего не отправляя (см. «Письма приложения»).

## Зачем пакет

Узлу нужна почта по двум поводам, и оба скучные: сказать человеку, что
случилось, и прочитать ответ, если человек ответил командой. Всё
остальное — почтовый клиент, а не кластер. Для этого нужны три
протокола, и у каждого своя роль:

| Протокол | Зачем |
|---|---|
| SMTP | отправить письмо |
| POP3 | забрать письма из ящика насовсем |
| IMAP | посмотреть письма, не отнимая их у человека; папки и флаги |

Пакет делает шесть вещей:

- **Не отдаёт пароль молча.** Без шифрования пароль уходит открытым
  текстом: base64 в AUTH — способ уложить байты в семь бит, а не
  спрятать их. Поэтому такой вход требует явного признания настройкой,
  а шифрование поднимается и с первого байта, и командой STARTTLS.
- **Собирает письмо целиком.** Тема с кириллицей, текст с разметкой,
  вложения, дата, идентификатор, точка в начале строки — каждая из этих
  мелочей, сделанная склейкой строк, портит письмо молча.
- **Читает чужие письма терпеливо.** Перенесённые заголовки, base64
  и quoted-printable, вложенные части, cp1251 из Windows: письмо не
  выбрасывается из-за того, что его собрали по чужим привычкам.
- **Не роняет узел.** Почта — не то дело, ради которого стоит его
  ронять: отказ возвращается причиной, у каждой операции свой срок,
  соединение закрывается в любом исходе.
- **Не пускает перевод строки в команды.** Адрес получателя часто
  приходит из формы, от человека; перевод строки в нём стал бы новой
  командой серверу, и такое письмо — отказ до сборки.
- **Держит письма приложения объявлениями.** Письмо, собранное склейкой
  строк в обработчике, — это текст, который расходится с разметкой,
  и отправка, которая держит запрос на сроке почтовика и теряет письмо
  с первым его отказом. Объявление собирает обе части из одного вида,
  очередь повторяет то, что сервер просил принести позже, а отказ
  «адреса нет» зарывает сразу.

Зависимости: [`tnt-tls`](https://github.com/tnt-skein/tnt-tls)
(шифрование поверх сокета), [`tnt-str`](https://github.com/tnt-skein/tnt-str)
(перевод чужих кодировок в UTF-8), [`tnt-id`](https://github.com/tnt-skein/tnt-id)
(ULID для `Message-ID`), [`tnt-log`](https://github.com/tnt-skein/tnt-log)
(запись о неотправленном письме), [`tnt-must`](https://github.com/tnt-skein/tnt-must)
(отказ настройки и проверки аргументов), [`tnt-fs`](https://github.com/tnt-skein/tnt-fs)
(файлы предпросмотра), [`tnt-metrics`](https://github.com/tnt-skein/tnt-metrics)
(ряды отправок), [`tnt-clock`](https://github.com/tnt-skein/tnt-clock)
(длительность разговора с сервером) и [`tnt-external`](https://github.com/tnt-skein/tnt-external)
(подмена сети, шифрования, часов и вывода в проверках). Шаблоны и очередь писем
приходят аргументами: движок [`tnt-template`](https://github.com/tnt-skein/tnt-template)
и любая очередь с `send`, например [`tnt-queue`](https://github.com/tnt-skein/tnt-queue), —
пакет знает их договор, а не их самих.

## Как пользоваться

```lua
local mail = require('tnt.mail')
```

| Вызов | Что делает |
|---|---|
| `mail.configure(opts)` | задаёт настройки; негодная — исключение сразу |
| `mail.send(letter)` | отправляет письмо; `true` либо `false, err` |
| `mail.render(letter)` | собирает письмо, не отправляя; текст либо `nil, err` |
| `mail.fetch(opts)` | забирает письма; список разобранных либо `nil, err` |
| `mail.folders()` | папки ящика по IMAP; список имён либо `nil, err` |
| `mail.status()` | что настроено, без паролей |
| `mail.parse.of(raw)` | разбирает письмо из строки |
| `mail.letters(opts)` | письма приложения объявлениями, см. «Письма приложения» |
| `mail.refusal.of(err)` | разбирает отказ отправки: род, повтор, код, получатель |
| `mail.text.of(html)` | простой текст из разметки |

Части пакета доступны и по отдельности — `mail.message` (сборка),
`mail.parse` (разбор), `mail.smtp`, `mail.pop3`, `mail.imap`
(разговор по протоколу) — для тех, кто собирает своё поведение.

### Настройки: `configure`

Настройки задаются один раз. Общие годятся всем трём протоколам — это
обычный случай, когда почтовик один; свои настройки протокола (разделы
`smtp`, `pop3`, `imap`) перекрывают общие.

```lua
mail.configure({
    from = { name = 'Узел storage-001-a', address = 'tarantool@example.org' },
    origin = 'storage-001-a',
    host = '127.0.0.1',
    smtp = { port = 3025 },
    imap = {
        port = 3143,
        username = 'duty@example.org',
        password = 'secret',
        allow_plaintext_auth = true,
    },
})
```

| Настройка | Где | Что | По умолчанию |
|---|---|---|---|
| `from` | общая | отправитель: строка или `{ name, address }` | — |
| `to` | общая | получатели по умолчанию | — |
| `origin` | общая | что стоит после `@` в `Message-ID` | `tarantool` |
| `host` | общая и своя | адрес сервера | — |
| `port` | своя | порт | по способу шифрования, см. ниже |
| `username`, `password` | общая и своя | учётная запись; пароль — строка либо функция-поставщик, у XOAUTH2 — токен | — |
| `timeout` | общая и своя | срок каждой операции, секунды | 5 |
| `helo` | общая и своя | имя в EHLO | `tarantool` |
| `tls` | общая и своя | `'none'`, `'starttls'` или `'direct'` | `'none'` |
| `verify` | общая и своя | проверять ли сертификат сервера | да |
| `ca_file`, `ca_path` | общая и своя | свои доверенные корни: файл и каталог | корни системы |
| `allow_plaintext_auth` | общая и своя | разрешить пароль без шифрования | `false` |
| `auth` | своя | один способ входа: у SMTP — из четырёх, у POP3 и IMAP — `xoauth2` | SMTP — выбирает сервер; POP3 и IMAP — имя и пароль |

Порт по умолчанию зависит от способа шифрования: у шифрования с первого
байта свои порты, потому что на обычном сервер ждёт открытого
приветствия и на рукопожатие TLS отвечает непониманием.

| `tls` | SMTP | POP3 | IMAP |
|---|---|---|---|
| `'none'` | 25 | 110 | 143 |
| `'starttls'` | 587 | 110 | 143 |
| `'direct'` | 465 | 995 | 993 |

587 у STARTTLS — порт сдачи письма, где шифрование и вход обязательны,
а 25 — порт передачи между серверами, где их обычно нет.

`verify = false` у протокола — решение, а не пропуск: общая настройка
его не перекрывает. Негодная настройка — ошибка того, кто настраивал,
и обнаруживается при `configure`, а не на первом письме посреди ночи:
неизвестный способ шифрования, способ входа, которого у протокола нет,
пароль не строкой и не функцией, имя или пароль с управляющим знаком
бросают исключение с текстом без места в коде.

```lua
local ok, err = pcall(mail.configure, { tls = 'ssl' })
--> false  неизвестный способ шифрования: ssl

local ok, err = pcall(mail.configure, { imap = { username = 'dev\r\nDELE 1' } })
--> false  имя IMAP: управляющий знак в «dev..DELE 1»
```

Имя и пароль сверяются у всех трёх протоколов, хотя SMTP отдаёт их
в base64: общее имя достаётся каждому, и годного для одного и негодного
для другого не бывает. Пароль в причине не показан — только протокол.

`mail.configure()` без аргумента возвращает умолчания.

### Письмо

| Поле | Что |
|---|---|
| `from` | отправитель; без него берётся из настроек, нет и там — отказ |
| `to`, `cc` | получатели: строка, `{ name, address }` или список таких |
| `bcc` | скрытые получатели: в конверте есть, в заголовках нет |
| `subject` | тема |
| `text` | простой текст |
| `html` | разметка; с ней письмо становится многочастным |
| `attachments` | вложения `{ name, type, content }`, см. «Вложения» |
| `headers` | свои заголовки: `{ ['X-Node'] = 'storage-001-a' }` |
| `date` | своя дата вместо времени сборки |
| `message_id` | свой идентификатор вместо ULID |
| `origin` | что стоит после `@` в `Message-ID` этого письма |

Имя человека кодируется только в записи таблицей: строка
`'Дежурный <duty@example.org>'` уходит в заголовок как есть, и имя
не из ASCII приедет байтами. Свои заголовки, дата и идентификатор
тоже уходят как есть — в них должен стоять печатный ASCII.

### Отправка: `send`

```lua
local ok, err = mail.send({
    to = { { name = 'Дежурный', address = 'duty@example.org' } },
    subject = 'Реплика отстала',
    text = 'Подробности одной строкой',
    html = '<p>или разметкой</p>',
})
```

Успех — `true`; отказ — `false` и причина строкой, и та же причина
ложится в журнал записью «письмо не отправлено». Причина называет шаг
разговора и ответ сервера целиком, с кодом:

```
получатель nobody@example.org: сервер ответил 550 — 550 5.1.1 mailbox unavailable
```

Код решает, стоит ли пробовать снова: 4xx — «попробуйте позже» (сервер
занят, ящик переполнен), 5xx — «не пробуйте больше» (адреса нет,
отказано навсегда). Повторять 5xx значит слать один и тот же отказ
до конца света. Повторов пакет не делает — это решает вызывающий.

До сервера письмо не доходит вовсе, если:

- адрес сервера SMTP не задан — `отправлять некуда: адрес сервера SMTP не задан`;
- отправителя нет ни в письме, ни в настройках;
- получателей нет ни в письме, ни в настройках — `получателей нет: письмо
  некому отдать`: будить сервер ради отказа незачем;
- вход с паролем идёт без шифрования и без `allow_plaintext_auth`;
- вложение негодно (см. «Вложения»);
- в адресе, своём заголовке, дате, идентификаторе или `origin`
  есть управляющий знак — перевод строки, табуляция, нулевой байт.

```lua
local ok, err = mail.send({ to = 'duty@example.org\r\nRCPT TO:<evil@example.org>', text = 'x' })
--> false  адрес в поле to: управляющий знак в «duty@example.org..RCPT TO:<evil@example.org>»
```

Управляющие знаки в причине показаны точкой: она идёт в журнал, и рвать
его тем же переводом строки незачем. Адрес не чинится, а отвергается:
исправленный адрес — уже не тот, что дали.

Соединение заводится на каждое письмо и закрывается в любом исходе,
с прощанием `QUIT`: сервер, которому его не сказали, держит соединение
до своего срока, а таких у него сотня.

### Сухой прогон: `render`

`mail.render(letter)` собирает письмо так же, как `send`, и не отправляет
его: видно, что именно уедет, без живого сервера. Негодное письмо — пара
`nil, err` с той же причиной, что у `send`, и письмо без отправителя
или без получателей тоже: `отправитель не задан: сервер не примет письмо
без него`, `получателей нет: письмо некому отдать`.

```lua
local text = assert(mail.render({ to = 'duty@example.org', subject = 'Отчёт', text = 'Тело' }))

print(text:match('Subject: ([^\r]*)'))  --> =?UTF-8?B?0J7RgtGH0ZHRgg==?=
```

### Что именно делает пакет с письмом

- тема с кириллицей кодируется по RFC 2047 (`=?UTF-8?B?...?=`);
- тело уходит в base64 строками по 76 символов — восьмибитный текст
  на пути через чужой сервер превращается в вопросительные знаки,
  а quoted-printable рвёт строки там, где ему удобно;
- письмо с `html` становится многочастным: простой текст первой частью,
  разметка второй — почтовые программы показывают последнюю, которую
  умеют, а те, что не умеют ничего, — первую;
- письмо с `attachments` становится `multipart/mixed`: первой частью —
  всё письмо, каким оно было бы без них (текст либо текст с разметкой),
  дальше по части на вложение;
- дата собирается вручную по-английски и в UTC: `os.date('%a %b')`
  зависит от локали процесса, и на узле с русской локалью письмо уехало
  бы с датой, которую не разберёт никто;
- у письма всегда есть `Message-ID` — без него почтовые серверы
  выдумывают его сами, и два письма одного узла слипаются в цепочку.
  Это ULID из `tnt-id`, `<01M2BE4B5V04106105ZZZZZZZY@storage-001-a>`
  (после собаки — `origin` письма или настроек, по умолчанию `tarantool`):
  время в старших знаках, и письма узла идут по нему в порядке сборки.
  Тайны в нём нет — время письма и так стоит в `Date`. Свой
  идентификатор передаётся полем `message_id` и ставится как есть;
- есть `MIME-Version: 1.0`, а скрытых получателей в заголовках нет:
  они на то и скрытые, в конверт разговора они попадают;
- точка в начале строки удваивается: одинокая точка означает конец
  письма, и текст с такой строкой без удвоения обрывается посередине,
  а остаток уходит серверу как команды.

### Вложения

Отчёт или выгрузка едут файлом, а не телом письма:

```lua
mail.send({
    to = 'duty@example.org',
    subject = 'Отчёт за сутки',
    text = 'Отчёт во вложении',
    attachments = {
        { name = 'report.csv', type = 'text/csv', content = csv },
        { name = 'снимок состояния.json', content = snapshot },
    },
})
```

У вложения три поля: `name` — имя файла, каким его увидит получатель;
`content` — содержимое строкой, любые байты; `type` — тип содержимого,
по умолчанию `application/octet-stream` (почтовая программа предложит
сохранить файл, а не покажет его как текст). Файл читает вызывающий:
пакет не ходит на диск и не знает, откуда взялись байты.

Что с вложением делает пакет:

- содержимое всегда base64 строками по 76 знаков — вложение чаще всего
  не текст, а у текста всё равно нашлась бы строка длиннее 998 байт;
- вложение объявляется `Content-Disposition: attachment`, и почтовые
  программы показывают его вложением, а не частью текста;
- имя из печатного ASCII идёт в кавычках как есть, любое другое —
  по RFC 2231 (`filename*=UTF-8''%D0%9E...`): кириллица доезжает
  именем, а перевод строки в имени не становится новым заголовком;
- тип проверяется до сборки — без косой это не тип, с управляющим
  знаком — ещё один заголовок, которого никто не писал;
- негодное вложение (не список, без имени, содержимое не строкой,
  тип не похож на тип) — отказ до сервера и запись «письмо
  не отправлено» в журнале: получатель ждёт отчёт, а не письмо о том,
  что отчёт был;
- границы частей случайные (`tnt-<uuid>`) и у каждого уровня свои:
  граница, встретившаяся в тексте письма, не разрежет его. Здесь
  `uuid` четвёртой версии, а не ULID, как у `Message-ID`: порядок границе
  не нужен, а угадать её должно быть нечем — у ULID время известно,
  и сосед в ту же миллисекунду отличается шагом не больше 2³².

```lua
local ok, err = mail.send({ to = 'duty@example.org', attachments = { { name = 'x.csv', content = 42 } } })
--> false  вложение №1: содержимое должно быть строкой, а не number
```

Забранное письмо отдаёт вложения в том же виде — `letter.attachments`,
список `{ name, type, content }`, — так что его можно переслать дальше
как есть. Вложением считается часть с именем файла (`filename`,
`filename*` по RFC 2231 или `name` из типа) либо объявленная
`Content-Disposition: attachment`; приложенный текст не становится
текстом письма. Имя вложения приходит в UTF-8, содержимое — байтами
как пришло, без перевода кодировки (см. «Кодировки чужих писем»).

### Забрать письма: `fetch`

```lua
local letters, err = mail.fetch({ via = 'imap', unseen = true, limit = 5 })

for _, letter in ipairs(letters or {}) do
    print(letter.subject, letter.from, letter.text)
end
```

По умолчанию IMAP: он смотрит письма, не отнимая их. POP3 просят явно —
там, где ящик принадлежит узлу целиком.

| Параметр | Что | По умолчанию |
|---|---|---|
| `via` | `'imap'` или `'pop3'` | `'imap'` |
| `limit` | сколько писем забрать | 10 |
| `folder` | папка (только IMAP) | `INBOX` |
| `unseen` | только непрочитанные (только IMAP) | нет |
| `mark_seen` | пометить прочитанными (только IMAP) | нет |
| `delete` | удалить забранное | нет |

Письма берутся с конца нумерации ящика, а нужны обычно последние:
у IMAP номера растут по приходу, и первыми идут свежие. У POP3 порядок
номеров выбирает сервер: Dovecot и GreenMail тоже нумеруют по приходу,
а сервер, который нумерует от свежего к старому, отдаёт по пределу
старые письма (см. «Чем пришлось поступиться»). Предел обязателен —
ящик, в который никто не заглядывал месяц, иначе приедет на узел
целиком. Параметры «только IMAP» POP3 не понимает: у него нет ни папок,
ни флагов.

Каждое письмо — разобранное (см. «Разбор письма»), и к нему добавлены:

| Поле | Что |
|---|---|
| `number` | номер письма в ящике на время этого соединения |
| `id` | устойчивое имя: `UID` у IMAP, `UIDL` у POP3; сервер без UIDL его не даёт |
| `raw` | письмо как пришло |

По IMAP письма читаются `BODY.PEEK[]`: чтение само по себе не ставит
отметку «прочитано», и узел, заглянувший в ящик, не отнимает у человека
признак непрочитанного письма. Удаление по IMAP — флаг `\Deleted`
и `EXPUNGE` в конце разговора. По POP3 `DELE` только помечает, а стирает
всё прощание `QUIT`: оборванное соединение — это «ничего не удалено»,
и повтор заберёт те же письма. Забирать дважды лучше, чем потерять
однажды.

Отказ — `nil` и причина с шагом разговора: `вход: a0001 NO неверный
пароль`, `папка Архив: …`, `письмо 3: …`. Настройки проверяются так же,
как у `send`: `забирать неоткуда: адрес сервера IMAP не задан`, запрет
пароля без шифрования, неизвестный `via`.

Папка, имя и пароль уходят в команду почти дословно, и управляющий знак
в них — перевод строки, табуляция, нулевой байт — это вторая команда
серверу, которой никто не писал. Такой забор не доходит до соединения:

```lua
mail.configure({ imap = { host = '127.0.0.1' } })

local letters, err = mail.fetch({ folder = 'INBOX"\r\na9 DELETE "Archive' })
--> nil  папка: управляющий знак в «INBOX"..a9 DELETE "Archive»
```

Папка часто приходит от человека, из формы, и она не чинится,
а отвергается: исправленная папка — уже не та, что дали. Токен
поставщика сверяется так же, уже полученный, — перед каждым входом:
`пароль: управляющий знак`, без самого пароля.

### Папки: `folders`

```lua
local folders, err = mail.folders()   --> { 'INBOX' } у нового ящика
```

Только IMAP: у POP3 папок не бывает. Имена приходят без кавычек, в том
виде, в каком их назвал сервер. Имя и пароль с управляющим знаком —
отказ до соединения, как у `fetch`.

### Что настроено: `status`

```lua
mail.status()
--> { from = {...}, smtp = { host, port, username, tls, auth, timeout }, pop3 = {...}, imap = {...} }
```

Паролей здесь нет и не будет: состояние читают и журнал, и панель,
и человек через плечо.

### Разбор письма: `parse.of`

`mail.parse.of(raw)` разбирает письмо из строки — так же, как `fetch`
разбирает забранные.

| Поле | Что |
|---|---|
| `from`, `to`, `cc`, `subject`, `date`, `message_id` | заголовки; тема — в UTF-8 |
| `text`, `html` | первая простая часть и первая разметка, в UTF-8 |
| `attachments` | вложения `{ name, type, content }` |
| `charset` | кодировка, в которой письмо пришло |
| `charset_error` | почему текст остался байтами, если перевести не вышло |
| `headers` | все заголовки по имени в нижнем регистре |
| `parts` | части: `kind`, `charset`, `disposition`, `name`, `options`, `headers`, `body`, `parts`, `charset_error` |

Чужие письма разбираются терпеливо: склеиваются перенесённые заголовки,
понимаются base64 и quoted-printable, многочастные письма разбираются
до трёх уровней вложенности, а непонятая часть остаётся сырой строкой —
показать сырое честнее, чем выбросить письмо целиком. Подробнее:

- тема, текст и имя вложения переводятся в UTF-8 по кодировке, которую
  объявило письмо, — см. «Кодировки чужих писем»;
- перевод строки между заголовками понимается любой — `\r\n`, `\n`
  или одинокий `\r`;
- пробел между двумя закодированными кусками заголовка выбрасывается
  (RFC 2047, 6.2): так длинную тему разбивают по словам. Пробел между
  куском и обычным словом — часть текста и остаётся, в том числе рядом
  с куском, который разобрать не вышло: `=?UTF-8?B?0KDQtdC/0LvQuNC60LA=?= lag`
  читается как «Реплика lag»;
- номер письма из ответа IMAP `SEARCH` — только слово из одних цифр:
  приписка `(MODSEQ …)` у CONDSTORE и прочие слова номерами не считаются,
  и письма не читаются по номерам, которых сервер не называл.

### Кодировки чужих писем

Свои письма пакет пишет в UTF-8, а чужие приходят как придётся: из
Windows — в cp1251, из старых почтовиков — в koi8-r. Байты такой
кодировки портит всякий, кто считает строку UTF-8: `str.upper` отдаёт
U+FFFD вместо букв, `slug` пуст, в панели и журнале каша. Поэтому разбор
переводит в UTF-8 то, что человек прочтёт как текст, — по кодировке,
которую объявило само письмо. Переводит `str.decode` из `tnt-str` поверх
встроенного `iconv` (см. раздел «Перекодировка» в документе
[`tnt-str`](https://github.com/tnt-skein/tnt-str/blob/main/docs/str.md)).

| Что | Откуда кодировка | Переводится ли |
|---|---|---|
| тема и прочие заголовки | закодированный кусок `=?windows-1251?B?...?=` или `?Q?` (RFC 2047) | да |
| текст, разметка и прочие части `text/*` | `charset` в `Content-Type` части | да |
| имя вложения | `filename*=windows-1251''%CE%F2...` (RFC 2231) либо кусок RFC 2047 в `name` | да |
| содержимое вложения | — | нет: файл — это байты, и выгрузка для Excel в cp1251 должна доехать cp1251; кодировка видна в `charset` части в `letter.parts` |
| части не `text/*` — `application/json` и прочие | — | нет, даже с `charset` |
| часть без `charset`, часть в UTF-8 (`utf-8`, `utf8`) | — | нет: гадать не из чего, а UTF-8 и так то, что нужно; битый байт UTF-8 остаётся на месте |
| сырое письмо `letter.raw` | — | нет |

```lua
local letter = mail.parse.of(table.concat({
    'Subject: =?windows-1251?B?0OXv6+jq4CDu8vHy4Ovg?=',
    'Content-Type: text/plain; charset=windows-1251',
    '',
    '\210\229\235\238\32\239\232\241\252\236\224', -- «Тело письма» в cp1251
}, '\r\n'))

print(letter.subject, letter.text, letter.charset)  --> Реплика отстала  Тело письма  windows-1251
print(utf8.len(letter.text))                        --> 11
```

`letter.charset` — кодировка, в которой письмо пришло, а не та, в которой
лежит текст: текст уже в UTF-8. Имя кодировки берётся без пробелов
по краям — `charset=windows-1251 ; format=flowed` понимается так же.

Перевести удаётся не всегда: кодировка незнакома ядру (`unknown-8bit`
от сломанного шлюза, опечатка в имени) либо в тексте есть байты не из неё
(0x98 в cp1251 не назначен). Разбор терпелив, письмо из-за этого
не отвергается и исключения нет:

- текст части остаётся байтами, как пришёл, а причина ложится рядом —
  в `charset_error` части и письма. У письма это первая причина из тех,
  что задели `letter.text` и `letter.html`: у письма из одной части
  саму часть в `letter.parts` не видно. У каждой части своя причина
  видна в `letter.parts`;
- закодированный кусок заголовка остаётся целиком, как пришёл: запись
  `=?unknown-8bit?B?...?=` — ASCII, она честна и никого дальше не портит
  (RFC 2047, 6.2). Так же остаётся кусок, который не base64;
- расширенное имя вложения уступает обычному `filename` или `name` —
  их пишут рядом ровно для тех, кто расширенного не понял, — а без них
  остаётся записью как пришла: `unknown-8bit''%CE%F2.csv`.

```lua
local broken = mail.parse.of(table.concat({
    'Subject: =?unknown-8bit?B?z/Do4uXy?=',
    'Content-Type: text/plain; charset=unknown-8bit',
    '',
    'as it came',
}, '\r\n'))

print(broken.subject)                     --> =?unknown-8bit?B?z/Do4uXy?=
print(broken.text, broken.charset_error)  --> as it came  кодировка «unknown-8bit» неизвестна
```

Имя вложения переводится, а его содержимое — нет:

```lua
local sent = mail.parse.of(table.concat({
    'Content-Type: multipart/mixed; boundary="edge"',
    '',
    '--edge',
    'Content-Type: text/csv; charset=windows-1251',
    "Content-Disposition: attachment; filename*=windows-1251''%CE%F2%F7%B8%F2.csv",
    '',
    '\207\240\232\226\229\242',
    '--edge--',
}, '\r\n'))

print(sent.attachments[1].name)                                   --> Отчёт.csv
print(sent.attachments[1].content == '\207\240\232\226\229\242')  --> true: байты cp1251
print(sent.parts[1].charset)                                      --> windows-1251
```

### Шифрование и пароли

Без шифрования письмо и пароль уходят открытым текстом. Поэтому вход
с паролем по незашифрованному соединению запрещён, пока его не признают
явно — настройкой `allow_plaintext_auth = true`. Забыть её нельзя,
а прочитав, уже не скажешь, что не знал.

```lua
mail.configure({ from = 'tarantool@example.org', smtp = { host = '127.0.0.1', port = 3025, username = 'dev', password = 'dev' } })

local ok, err = mail.send({ to = 'duty@example.org', text = 'x' })
--> false  вход с паролем по незашифрованному соединению запрещён: поднимите TLS или признайте это настройкой allow_plaintext_auth
```

Шифрование даёт `tnt-tls` поверх системной OpenSSL. У каждого протокола
свой способ его поднять, и они не взаимозаменяемы:

| Настройка | Что происходит | Порты |
|---|---|---|
| `tls = 'none'` | открытый текст; пароль только с `allow_plaintext_auth` | 25, 110, 143 |
| `tls = 'direct'` | шифрование с первого байта | 465, 995, 993 |
| `tls = 'starttls'` | разговор начинается открытым, потом переходит на TLS | 587, 110, 143 |

Открытый вход годится там, где сеть до сервера доверенная: почтовый релей
на том же хосте или в том же контуре. Для внешнего почтовика — `direct`
либо `starttls`.

Сертификат проверяется по умолчанию, по корням системы. Релей в своём
контуре часто подписан своим корнем — его называют `ca_file` или
`ca_path`; `verify = false` выключает проверку совсем, и тогда TLS
защищает от того, кто слушает сеть, но не от того, кто встал посередине.

```lua
mail.configure({
    from = 'tarantool@example.org',
    smtp = { host = 'relay.internal', tls = 'starttls', ca_file = '/etc/ssl/relay-ca.pem', username = 'node', password = secret },
})
```

После STARTTLS прежнее соединение негодно: всё дальше — вход, письмо,
прощание — идёт по защищённому, и закрывается тоже оно, в любом исходе.
По SMTP после перехода пакет здоровается заново: список расширений до
и после шифрования разный, AUTH сервер объявляет как раз после, а старый
список пришёл открытым текстом, и верить ему нельзя. Сервер, который
не предлагает STARTTLS, или рукопожатие, которое не удалось, — отказ:
продолжать открытым текстом значило бы отдать пароль.

### Способы входа

Сервер SMTP называет способы входа в ответе на EHLO, и пакет выбирает из них
сам: CRAM-MD5, потом PLAIN, потом LOGIN. Настройка `smtp.auth` называет
ровно один способ — и тогда другой не пробуется, даже если сервер
предлагает только его: перейти с CRAM-MD5 на PLAIN значило бы отдать
открытым текстом пароль, который обещали не отдавать.

| `smtp.auth` | Что уходит по проводу | Когда нужен |
|---|---|---|
| `'cram-md5'` | имя и HMAC-MD5 от вызова сервера на ключе-пароле (RFC 2195); пароля на проводе нет | вход без TLS в доверенной сети; `allow_plaintext_auth` не нужен |
| `'plain'` | имя и пароль одной строкой в base64 | сервер предлагает несколько, а нужен именно этот |
| `'login'` | имя и пароль по очереди в base64 | то же |
| `'xoauth2'` | имя и токен OAuth 2.0 в base64; сам собой не выбирается | Gmail, Microsoft 365: пароля у ящика нет, в `password` — токен либо его поставщик |

```lua
mail.configure({
    from = 'tarantool@example.org',
    smtp = { host = '127.0.0.1', port = 2025, username = 'dev', password = 'dev', auth = 'cram-md5' },
})
```

У POP3 и IMAP вход — имя и пароль (`USER` и `PASS`, `LOGIN`), а сверх
него один способ — XOAUTH2 по настройке `auth = 'xoauth2'`: `AUTH XOAUTH2`
у POP3 и `AUTHENTICATE XOAUTH2` у IMAP. Другого им не задать:

```lua
local ok, err = pcall(mail.configure, { imap = { auth = 'plain' } })
--> false  неизвестный способ входа IMAP: plain
```

**Пароль — строка либо функция-поставщик.** Токен OAuth 2.0 живёт час:
взятый при настройке, к вечеру он мёртв. Поставщик — функция без
аргументов, отдающая токен строкой либо `nil, err`, — зовётся перед
каждым входом, по каждому из трёх протоколов, и сам решает, отдать
прежний токен или взять новый по сроку. Такую функцию отдаёт клиент
OAuth 2.0 приложения; пакет почты о нём не знает.

```lua
-- Gmail: отправка и чтение одним ящиком, токен — у поставщика.
mail.configure({
    from = 'node@gmail.com',
    username = 'node@gmail.com',
    password = token,                     -- function() → 'ya29.…' либо nil, err
    smtp = { host = 'smtp.gmail.com', tls = 'starttls', auth = 'xoauth2' },
    imap = { host = 'imap.gmail.com', tls = 'direct', auth = 'xoauth2' },
})
```

Поставщик зовётся до соединения и только если вход будет — задано имя:
не получив токена, незачем будить сервер. Его отказ — отказ письма или
забора со словами поставщика, бросок — тоже отказ, а не исключение:

```lua
local ok, err = mail.send({ to = 'duty@example.org', text = 'x' })   -- поставщик: nil, 'токен обновления отозван'
--> false  пароль не получен: токен обновления отозван
```

Мелочи, ради которых это написано, а не взято готовым:

- отказ XOAUTH2 сервер отдаёт в два шага — продолжение с причиной
  в base64 (JSON со статусом: `334` у SMTP, `+` у POP3 и IMAP)
  и окончательный отказ после пустой строки от клиента; пакет шлёт
  пустую строку и называет обе части, иначе `535` читался бы ответом
  на MAIL FROM, а IMAP и POP3 стояли бы до срока;
- у POP3 и IMAP начальный ответ XOAUTH2 идёт строкой после продолжения,
  а не в самой команде: команда POP3 не длиннее 255 байт (RFC 5034, §4),
  а токен Microsoft 365 длиннее килобайта; у IMAP так понимает и сервер
  без SASL-IR (RFC 4959). Сервер без XOAUTH2 отказывает на саму команду,
  и токен ему не уходит;
- старая запись `250-AUTH=CRAM-MD5 PLAIN` понимается наравне
  с `250-AUTH CRAM-MD5 PLAIN`; способы сравниваются словами целиком,
  и `PLAIN-CLIENTTOKEN` не принимается за PLAIN;
- у POP3 и IMAP `auth` понимает только `xoauth2`: настройка, которую
  протокол молча пропустил бы, обещала бы то, чего нет; опечатка в имени
  способа — исключение при `configure`, а не отказ на первом письме.

Сверено на 3.8 живыми серверами: Mailpit (1.21 и свежий) и GreenMail 2.1
предлагают только PLAIN и LOGIN; smtp4dev 3.15 предлагает все четыре,
проверяет отзыв CRAM-MD5 по паролю (чужой — `535`), а команду XOAUTH2
разбирает, но токен сверяет только с настоящим поставщиком OAuth 2.0.
XOAUTH2 по IMAP и POP3 не знают ни GreenMail 2.1, ни smtp4dev 3.15:
живая проверка сверяет на GreenMail, что отказ приходит сразу его
словами, а не молчанием до срока, а удачный вход проверяется двойником.
HMAC-MD5 даёт встроенный `crypto.hmac.md5_hex`; ответ на вызов из
RFC 2195 сходится с примером дословно.

По POP3 вход — `USER` и `PASS`, по IMAP — `LOGIN`, если не задан XOAUTH2. Имя, пароль и папка
IMAP идут в кавычках, и кавычка или обратная косая внутри них
экранируются (RFC 3501): пароль с кавычкой иначе оборвал бы строку.
CR и LF в кавычках RFC 3501 запрещает, а у POP3 кавычек нет вовсе,
поэтому управляющий знак не экранируется, а отвергается до разговора —
и при XOAUTH2 тоже: имя и токен там склеены знаком `\1`, и знак внутри
них дописал бы в запись чужое поле.

### Журнал

Неотправленное письмо — запись уровня `warn` журнала `tnt.mail`
с сообщением «письмо не отправлено» и полями `to` (адреса строкой)
и `err`. Одна запись на любой отказ: и когда сервера нет, и когда
письмо не собралось, — иначе отчёт без вложения пропал бы тише, чем
письмо без сервера. Удачная отправка и забор писем в журнал не пишут.
Пароля в журнале нет.

### Ряды метрик

Журнал говорит о каждом неотправленном письме строкой. Почтовик,
который третий час отвечает «попробуйте позже», в журнале — сотня
одинаковых строк, а рядом — доля, которую видно на графике и на которую
ставится тревога. Поэтому каждая отправка `send` ложится в ряды реестра
встроенного `metrics` ([`tnt-metrics`](https://github.com/tnt-skein/tnt-metrics),
«Прикладные ряды»):

| Ряд | Род | Метки | Что значит |
|---|---|---|---|
| `mail_sent_total` | counter | `transport`, `outcome`: `sent`, `deferred`, `rejected`, `failed`, `invalid` | сколько писем отправлялось: отправлено либо род отказа |
| `mail_send_duration_seconds` | histogram | `transport` | сколько шёл разговор с сервером |

- **Итог отказа — его род**, тот же, что у `mail.refusal.of` и у очереди
  писем (ниже, «Разбор отказа доставки»): 4xx — `deferred`, 5xx —
  `rejected`, без кода — `failed`. Отказ до сервера — тоже отказ:
  сервер не задан и пароль без шифрования — `failed` (чинятся настройки,
  а не письмо), письмо без отправителя, без получателей и несобранное —
  `invalid`. Текст отказа в метку не идёт: его пишет чужой сервер
  и называет в нём получателя, и меткой он был бы без границы.
- **Длительность — разговор с сервером**: соединение, шифрование, вход
  и передача письма, у отказа тоже, монотонными часами. Письмо,
  отвергнутое до сервера, в ней не видно: его время — проверка настроек
  и сборка, и сервер тут ни при чём. Корзины — от 10 мс до минуты:
  релей на том же хосте отвечает за миллисекунды, а зависший держит
  каждую операцию до её срока.
- **Способ — метка `transport`**: `send` уходит по SMTP, и значение
  у неё `smtp`. Потолок — десять способов.
- **Считается `mail.send`** — и прямой вызов, и письма объявлениями
  с почтой по умолчанию (`letters:send`, обработчик очереди).
  Разговор по частям (`mail.smtp`), своя почта писем (`mailer`) и забор
  писем в ряды не идут.

Три отправки: удачная и отказ 550 — двойнику сервера, подменённому
так же, как в разделе ниже («Подмена в проверках»), — и третья на порт,
где сервера нет:

```lua
mail.send({ to = 'duty@example.org', subject = 'Реплика отстала', text = 'Подробности' })
--> true
mail.send({ to = 'nobody@example.org', subject = 'Реплика отстала', text = 'Подробности' })
--> false  получатель nobody@example.org: сервер ответил 550 — 550 5.1.1 mailbox unavailable
mail.send({ to = 'duty@example.org', subject = 'Реплика отстала', text = 'Подробности' })
--> false  соединение с 127.0.0.1:2525 не установлено
```

Выкладка узла после них (строки `_bucket` опущены; порядок рядов
и меток у плагина произвольный):

```
# HELP mail_send_duration_seconds Сколько шёл разговор с почтовым сервером: соединение, вход и передача письма
# TYPE mail_send_duration_seconds histogram
mail_send_duration_seconds_sum{transport="smtp"} 0.00081386597594246
mail_send_duration_seconds_count{transport="smtp"} 3
# HELP mail_sent_total Сколько писем отправлялось: по способу и итогу — отправлено либо род отказа
# TYPE mail_sent_total counter
mail_sent_total{outcome="sent",transport="smtp"} 1
mail_sent_total{outcome="rejected",transport="smtp"} 1
mail_sent_total{outcome="failed",transport="smtp"} 1
```

### Подмена в проверках

Сеть и шифрование — внешние зависимости транспорта, и в проверках
их подменяют через `_set_source`: `connect(host, port, timeout)` отдаёт
сокет (нужны `read`, `write`, `close`, как у `socket.tcp_connect`),
`connect_secure(opts)` — соединение с шифрованием с первого байта,
`upgrade(socket, opts)` — соединение после STARTTLS.

```lua
local transport = require('tnt.mail.transport')

-- Сервер, который отвечает по списку и запоминает сказанное.
local replies = { '220 готов', '250 привет', '250 отправитель', '250 получатель', '354 давайте', '250 принято', '221 пока' }
local said = {}

transport._set_source({
    connect = function()
        return {
            read = function()
                return table.remove(replies, 1) .. '\r\n'
            end,
            write = function(_, text)
                table.insert(said, text)

                return #text
            end,
            close = function() end,
        }
    end,
})

mail.configure({ from = 'tarantool@example.org', smtp = { host = 'почтовик' } })
assert(mail.send({ to = 'duty@example.org', subject = 'Проверка', text = 'тело' }))
assert(said[1] == 'EHLO tarantool\r\n')
assert(said[2] == 'MAIL FROM:<tarantool@example.org>\r\n')

transport._set_source(nil)  -- снова настоящая сеть
```

## Письма приложения: объявление, очередь, предпросмотр

Письмо о тревоге узел собирает сам, одной строкой. Письма приложения —
«подтвердите почту», «вам ответили», «задание выполнено» — устроены
иначе: у каждого своя тема, свои получатели и своё тело по шаблону,
а шлют их из обработчика запроса, которому ждать почтовика нельзя.
`mail.letters` держит такие письма объявлениями:

```lua
local mail = require('tnt.mail')
local queue = require('tnt.queue')
local template = require('tnt.template')

local letters = mail.letters({
    views = template.new({ path = 'resources/views' }),
    queue = queue.declare('mail', { ttr = 60 }),
    from = { name = 'Пример', address = 'noreply@example.org' },
})

letters:declare('confirm', {
    subject = 'Подтвердите почту',
    to = function(data)
        return { name = data.name, address = data.email }
    end,
    view = 'mail.confirm',
    example = { name = 'Мария', email = 'maria@example.org', link = 'https://example.org/confirm?token=a1&user=7' },
})

local id, err = letters:queue('confirm', { name = user.name, email = user.email, link = link })
```

```html
{{-- resources/views/mail/confirm.thtml.lua --}}
@extends('mail.layout')
@section('title', 'Подтвердите почту')
@section('content')
<p>{{ name }}, подтвердите почту: <a href="{{ link }}">подтвердить</a>.</p>
<p>Ссылка действует сутки.</p>
@endsection
```

| Вызов | Что делает |
|---|---|
| `mail.letters(opts)` | заводит письма; негодная настройка — исключение на строке вызывающего |
| `letters:declare(name, declaration)` | объявляет письмо; отдаёт те же письма — объявления идут цепочкой |
| `letters:names()` | имена объявленных писем по алфавиту |
| `letters:build(name, data)` | письмо таблицей: получатели, тема, `text`, `html` |
| `letters:render(name, data)` | письмо целиком, как уйдёт серверу, либо `nil, err` |
| `letters:send(name, data)` | отправляет сразу, в файбере вызывающего: `true` либо `nil, err` |
| `letters:queue(name, data, opts)` | ставит письмо в очередь: `id` сообщения либо `nil, err` |
| `letters:handler()` | обработчик для `queue:consume` |
| `letters:deliver(message)` | то же без обёртки: отправляет письмо из сообщения очереди |
| `letters:preview(directory, names)` | кладёт письма в каталог для браузера: `{ index, letters }` либо `nil, err` |

Настройки `mail.letters`:

| Ключ | Что | По умолчанию |
|---|---|---|
| `views` | движок `tnt-template`: `render(name, data)` и `render_text(name, data)` | нет; без него не объявить ни одного письма |
| `queue` | очередь с `send(body, opts)`, например `tnt-queue` | нет; без неё нет `queue` |
| `from` | отправитель писем поверх настроек почты | из `mail.configure` |
| `mailer` | почта с `send(letter)` и `render(letter)` | сам `tnt.mail` с его настройками |

Незнакомый ключ, движок без `render_text`, очередь без `send` —
исключение на строке вызывающего:

```lua
mail.letters({ view = views })
--> error: настройки писем: ключа «view» нет, есть from, mailer, queue, views
```

### Объявление: `declare`

| Поле | Что |
|---|---|
| `subject` | тема: строка либо функция данных; обязательна |
| `view` | шаблон разметки; простой текст выводится из неё же |
| `text_view` | свой шаблон простого текста вместо выведенного из разметки |
| `to`, `cc`, `bcc` | получатели, как у письма `send`: значение либо функция данных |
| `from` | отправитель этого письма поверх `from` писем и настроек почты |
| `headers` | свои заголовки |
| `attachments` | вложения `{ name, type, content }`, см. «Вложения, кодировки, подписи» |
| `example` | данные для предпросмотра: таблица либо функция |

Нужен хотя бы один вид — `view` или `text_view`. Всё, кроме видов
и примера, — значение либо функция, которую зовут с данными письма:
получатель лежит в данных, а тема бывает от них зависимой. Шаблоны видят
те же данные.

```lua
letters:declare('replied', {
    subject = function(data)
        return ('Ответ в теме «%s»'):format(data.thread)
    end,
    to = function(data)
        return data.email
    end,
    view = 'mail.replied',
    text_view = 'mail.replied_text',
    example = function()
        return { name = 'Мария', email = 'maria@example.org', thread = 'Отставание реплики', reply = 'Перезапустили узел', link = 'https://example.org/threads/7' }
    end,
})
```

Ошибка объявления — исключение на строке вызывающего, при загрузке,
а не на первом письме посреди ночи:

| Что сделано не так | Текст броска |
|---|---|
| имя объявлено второй раз | `письмо confirm уже объявлено` |
| вида нет | `письмо empty: вида нет — дайте view либо text_view` |
| письмам не дали шаблоны | `письмо confirm рисуется шаблоном, а views письмам не дали` |
| незнакомый ключ | `письмо typo: ключа «veiw» нет, есть attachments, bcc, cc, example, from, headers, subject, text_view, to, view` |
| тема не строка и не функция | `письмо number.subject — строка или функция или вызываемая таблица, а не 7` |

Собирается письмо при `build`, `render`, `send`, `queue` и `preview`,
в файбере вызывающего. Письмо, которого нет, данные не таблицей, функция
темы, отдавшая не строку, и ошибка в шаблоне — исключение без места
с именем письма: так пишет программист, а не получатель.

```
письма missing нет; объявлены: confirm, replied
письмо replied: тема — строка, а не number
письмо confirm: данные — таблица, а не строка
```

### Один вид — обе части

Письмо с разметкой уходит двумя частями: простой текст первой, разметка
второй. Держать текст вторым шаблоном рядом с разметкой — значит однажды
поправить одно и забыть другое: ссылка подтверждения в тексте ведёт
на старый адрес, и получатель, чья программа показывает простой текст,
подтвердить почту не может. Поэтому простой текст выводится из той же
разметки, какой её увидит браузер (`mail.text.of`):

```lua
local letter = letters:build('confirm', { name = 'Мария', email = 'maria@example.org', link = 'https://example.org/c?a=1&b=2' })

letter.html   --> …<p>Мария, подтвердите почту: <a href="https://example.org/c?a=1&amp;b=2">подтвердить</a>.</p>…
letter.text   --> Мария, подтвердите почту: подтвердить (https://example.org/c?a=1&b=2).
              -->
              --> Ссылка действует сутки.
              -->
              --> -- 
              --> Команда примера
```

Что делает вывод текста:

- `head`, `style`, `script`, `title`, `template`, заметки `<!-- -->`
  и объявления `<!DOCTYPE>` выпадают целиком;
- пробелы и переводы строк разметки сжимаются в один пробел — как их
  показывает браузер; внутри `pre` они остаются как есть;
- абзац, заголовок, таблица, цитата, `pre`, `hr` и список отделены
  пустой строкой, а `div`, строка таблицы и пункт списка начинаются
  с новой строки; `br` — перевод строки, и два подряд — пустая строка;
  пустых строк подряд больше одной не бывает;
- пункт — «- » либо «1. », пункт вложенного списка — с отступом в два
  пробела и без пустой строки над ним;
- ссылка — текст и адрес в скобках; ссылка, текст которой и есть адрес
  (или адрес за `mailto:`), — адрес один раз; ссылка без текста — адрес;
  ссылка внутри страницы (`#…`) — только текст;
- картинка — её `alt`;
- знаки `&amp;`, `&laquo;`, `&#8212;`, `&#x416;` — буквами UTF-8;
  управляющий знак, суррогат и номер за пределом Юникода остаются записью
  как есть;
- строка `--` — разделитель подписи `-- ` (см. «Подписи»).

Свой текст там, где выведенный не годится, — `text_view`. Он рисуется
`views:render_text`: простым текстом, без экранирования HTML. `O'Brien`
и `a < b` в тексте письма остаются собой, а не `O&#39;Brien`:

```html
{{-- resources/views/mail/replied_text.thtml.lua --}}
{{ name }}, в теме «{{ thread }}» новый ответ:

{{ reply }}

{{ link }}
```

Письмо только с `text_view` уходит одним простым текстом, без разметки.

### Отправка сразу: `send` и `render`

`letters:send(name, data)` собирает письмо и отправляет его почтой сразу,
в файбере вызывающего, — там, где ждать почтовика можно: в консольной
команде, в фоновой работе. Удача — `true`, отказ — `nil` и отказ
доставки (см. «Разбор отказа доставки»):

```lua
local sent, err = letters:send('confirm', { name = 'Мария', email = 'nobody@example.org', link = link })

err.kind        --> 'rejected'
err.retriable   --> false
err.status      --> '5.1.1'
err.recipient   --> 'nobody@example.org'
tostring(err)   --> получатель nobody@example.org: сервер ответил 550 — 550 5.1.1 no such user
```

Письмо собирается так же, как соберёт его почта, до сервера: негодное —
вложение, управляющий знак в адресе из формы, нет отправителя — отказ
`invalid` с именем письма, и почта его не видит:

```lua
local sent, err = letters:send('confirm', { name = 'x', email = 'a@b\r\nRCPT TO:<evil@example.org>', link = link })
--> nil  письмо confirm: адрес в поле to: управляющий знак в «a@b..RCPT TO:<evil@example.org>»
```

`letters:render(name, data)` — то же без отправки: письмо целиком
строкой либо `nil` и тот же отказ.

### Отправка очередью: `queue` и `handler`

Обработчик запроса письмо не отправляет, а ставит в очередь: запрос
отвечает сразу, а письмо, которому почтовик сказал «попробуйте позже»,
очередь принесёт ещё раз.

```lua
local id, err = letters:queue('confirm', data, { delay = 5 })

queue.declare('mail', { ttr = 60 }):consume(letters:handler(), { workers = 2, max_attempts = 5 })
```

- **Письмо собирается при постановке**, в файбере вызывающего, и уходит
  в очередь готовым, простыми данными: `{ letter = 'confirm', mail = { … } }`.
  Ошибка в шаблоне и негодный адрес падают у того, кто отправлял,
  а не зарытым сообщением через час; негодное письмо в очередь не идёт —
  отказ `invalid`.
- **Опознаватель и дата ставятся при постановке** и едут с письмом:
  повтор после обрыва уходит тем же письмом с тем же `Message-ID`,
  и получатель узнаёт его, а не получает второе. Дата — миг постановки,
  а не миг удачной попытки: письмо составлено тогда.
- **Настройки отправки** — третий аргумент — уходят очереди как есть:
  у `tnt-queue` это `delay`, `ttl`, `priority`, `key`, `headers`, `id`,
  `timeout`. Отказ очереди приходит как есть — у `tnt-queue`
  `TntStorageFailure`.
- **Отправка в транзакции `box`** у `tnt-queue` становится её частью:
  «сохранили пользователя и поставили письмо» — одна фиксация, а откат
  уносит и письмо.

Обработчик отдаёт письмо почте, и итог его — по договору очереди
([«Итог обработчика»](https://github.com/tnt-skein/tnt-queue/blob/main/docs/queue.md#итог-обработчика)
у `tnt-queue`): удача подтверждает, отказ — пара `nil, err`,
и повтор решает `err.retriable`:

| Почта ответила | Отказ | Очередь |
|---|---|---|
| письмо принято | — | подтверждает |
| 4xx: ящик полон, сервер занят | `deferred` | возвращает с отступом, после `max_attempts` зарывает |
| без кода: сети нет, срок вышел, шифрование, настройки, токен | `failed` | то же |
| 5xx: адреса нет, отказано навсегда | `rejected` | зарывает сразу |
| в сообщении нет письма | `invalid` | зарывает сразу |

Зарытое лежит у `tnt-queue` в спейсе `<имя>_dead` с причиной — словами
почтовика целиком; вернуть его после починки — `queue:kick`. Письма
одного адресата порядка не держат: порядок между письмами очередь
не обещает, а ключ `key` держит его только внутри себя.

### Разбор отказа доставки: `refusal`

Отказ отправки — строка, и строка эта — договор пакета: шаг разговора,
код ответа и ответ сервера целиком. `mail.refusal.of(err)` превращает её
в решение:

```lua
local refusal = mail.refusal.of('получатель nobody@example.org: сервер ответил 550 — 550 5.1.1 mailbox unavailable')

refusal.kind        --> 'rejected'
refusal.retriable   --> false
refusal.code        --> 550
refusal.status      --> '5.1.1'
refusal.recipient   --> 'nobody@example.org'
refusal.message     --> получатель nobody@example.org: сервер ответил 550 — 550 5.1.1 mailbox unavailable
```

| Поле | Что |
|---|---|
| `kind` | `rejected` (5xx), `deferred` (4xx), `failed` (без ответа сервера либо непонятый ответ), `invalid` (письмо не собралось) |
| `retriable` | стоит ли пробовать снова: нет у `rejected` и `invalid` |
| `code` | код ответа SMTP |
| `status` | расширенный код RFC 3463: `5.1.1` — ящика нет, `4.2.2` — ящик полон, `5.7.1` — отказано политикой |
| `recipient` | получатель, которого сервер не принял |
| `message` | причина целиком; ею же отказ читается строкой |

Род решает первая цифра кода (RFC 5321, 4.2.1): 5xx — «не пробуйте
больше», повторять его — слать один и тот же отказ до конца света;
4xx — «попробуйте позже», и зарыть его — потерять письмо. Отказ без кода
повторяется: сеть, настройки и поставщик токена чинятся без правки
письма, а после исчерпанных попыток зарытое видно человеку. Код ищется
только в словах отправки «сервер ответил»: число в ответе сервера
(`timeout 550`) кодом не становится.

По `recipient` и `status` приложение решает, что делать с адресом:
на ящик, которого нет (`5.1.1`), слать больше незачем.

### Предпросмотр: `preview` и `make mail-preview`

Посмотреть письмо иначе можно только отправив его. Предпросмотр собирает
каждое объявленное письмо с данными его `example` так же, как отправка,
и кладёт в каталог:

| Файл | Что | Чем смотреть |
|---|---|---|
| `index.html` | оглавление: письмо, тема и получатели, как их покажет почтовая программа, ссылки на файлы | браузером |
| `<имя>.html` | часть с разметкой | браузером |
| `<имя>.txt` | простой текст | браузером либо редактором |
| `<имя>.eml` | письмо целиком, как уйдёт серверу | почтовой программой |

```lua
local files, err = letters:preview('var/mail-preview')
--> { index = 'var/mail-preview/index.html', letters = { { name = 'confirm', subject = 'Подтвердите почту',
-->     to = 'Мария <maria@example.org>', html = 'var/mail-preview/confirm.html',
-->     text = 'var/mail-preview/confirm.txt', eml = 'var/mail-preview/confirm.eml' }, … } }

letters:preview('var/mail-preview', { 'confirm' })   -- только названные
```

Разметка и текст начинаются меткой порядка байтов UTF-8, а после неё —
ровно то, что получит ящик: кодировку части в письме называет её
заголовок, у файла заголовков нет, и по метке браузер читает кириллицу
как UTF-8, даже если рамка письма не объявила `<meta charset>`. Письмо
без разметки ложится текстом и письмом целиком. Имя файла — имя письма,
где всё, кроме букв, цифр, точки, дефиса и подчёркивания, заменено `_`.
Письмо, которое не собралось, и каталог, куда не пишется, — отказ
`nil, err` с именем письма либо путём.

Цель сборки делает то же для модуля, который отдаёт письма:

```sh
make mail-preview LETTERS=app.mail                       # в var/mail-preview
make mail-preview LETTERS=app.mail MAIL_PREVIEW_OUT=var/letters
make mail-preview LETTERS=test.fixtures.letters          # письма-образцы из корня пакета
```

```
var/mail-preview/index.html
var/mail-preview/confirm.html
var/mail-preview/replied.html
```

Модуль — обычный модуль Lua, который отдаёт `mail.letters` с объявлениями
и примерами. Цель берёт установленные пакеты, а настройки почты — те, что
модуль задал сам: сервер для предпросмотра не нужен, нужен отправитель.
Код выхода — 0 при удаче, 1 при отказе (модуль не загрузился, письмо
не собралось), 2 без `LETTERS`. Вход цели — `require('tnt.mail.preview').main(module, directory)`.

### Вложения, кодировки, подписи

**Вложения.** Поле `attachments` объявления — список `{ name, type,
content }` либо функция данных, которая его отдаёт: отчёт за день
приложен к письму его данными, а не файлом с диска.

```lua
letters:declare('report', {
    subject = 'Отчёт за сутки',
    to = 'duty@example.org',
    view = 'mail.report',
    attachments = function(data)
        return { { name = 'отчёт.csv', type = 'text/csv', content = data.csv } }
    end,
})
```

Вложение проверяется при постановке и при отправке так же, как у `send`
(см. «Вложения»): негодное — отказ `invalid` до сервера и до очереди.
Письмо в очереди несёт вложения с собой, байтами в спейсе: большой файл
лучше положить ссылкой со сроком — скажем, у ведра S3 это `presign`
из [`tnt-s3`](https://github.com/tnt-skein/tnt-s3), — чем вложением
в каждое письмо.

**Кодировки.** Свои письма пакет пишет в UTF-8, и объявлениям ничего
делать не нужно: тема и имя получателя кодируются по RFC 2047, имя
вложения — по RFC 2231, текст и разметка — base64 строками по 76 знаков
с `charset=UTF-8` у каждой части. Шаблон отдаёт UTF-8 — Lua-строки
в шаблоне и данные приложения в нём и так. Данные в cp1251 переводят
в UTF-8 до письма — `str.decode` из `tnt-str`: шаблон байты не
перекодирует, и письмо ушло бы кашей. Вложение не перекодируется:
выгрузка для Excel в cp1251 доезжает cp1251.

**Подписи.** Общая подпись писем — «Команда такого-то», ссылка
на отписку, адрес — живёт в рамке, от которой наследуют виды
(`@extends('mail.layout')`): поправить её надо в одном месте. Отделяет
её строка из двух дефисов, и в простом тексте она становится
разделителем подписи `-- ` с пробелом (RFC 3676, 4.3): по нему почтовые
программы узнают подпись и не цитируют её в ответе. Пробел в конце
строки разметка съела бы, поэтому ставит его вывод текста, а в своём
`text_view` его пишут сами.

```html
{{-- resources/views/mail/layout.thtml.lua --}}
<!DOCTYPE html>
<html lang="ru">
<head><meta charset="utf-8"><title>@yield('title')</title></head>
<body>
@yield('content')
<p>--<br>Команда примера</p>
</body>
</html>
```

Криптографической подписи — DKIM, S/MIME — пакет не ставит. DKIM
подписывает домен отправителя, и ключ домена живёт у почтовика, который
выпускает письма в мир: подпись узла ломалась бы на первой правке
заголовков релеем, а ключ пришлось бы раздать каждому узлу кластера.
S/MIME — подпись человека, а письма приложения шлёт не человек.

## Чем пришлось поступиться

- **Соединение на каждое письмо.** Пула соединений и отправки пачкой
  нет: узел шлёт письмо о том, что случилось, а не рассылку, и держать
  открытое соединение ради редкого письма — значит держать ещё и его
  отказы. Сотня писем подряд — сотня соединений.
- **У `send` повторов нет.** Код ответа в причине говорит, временный
  отказ или окончательный; когда и сколько раз повторять, решает
  вызывающий — у письма о тревоге и у отчёта за сутки разные сроки
  годности. Письма приложения повторяет очередь (`letters:queue`),
  и правило у неё одно: 5xx зарывается сразу, прочее повторяется.
- **Отказ 5xx на входе тоже зарывает письмо.** Неверный пароль
  и отозванный токен — `535`, и очередь зарывает письмо сразу, хотя
  починка настроек его спасла бы. Повторять вход с тем же паролем —
  тот же отказ на каждом письме; зарытые возвращает `queue:kick` после
  починки.
- **Текст из разметки — простой.** Таблица выходит строками слов через
  пробел, без колонок, жирное и курсив — без отметок, цитата — абзацем
  без `>`. Письму, где это важно, дают `text_view`. Знак `>` внутри
  значения свойства тега (`title="a > b"`) обрывает тег.
- **Письмо в очереди несёт всё с собой.** Тело, разметка и вложения
  лежат в спейсе очереди до отправки: так ошибка шаблона видна тому,
  кто отправлял, и повтор уходит тем же письмом. Цена — место в спейсе
  и правка шаблона, которая не касается уже поставленных писем.
- **Предпросмотр рисует пример, а не настоящие данные.** Письмо, которое
  ломается только на пустом поле, в предпросмотре с полным примером
  выглядит годным; пример в объявлении стоит держать похожим на правду.
- **Тело всегда base64.** Письмо на треть длиннее, чем в восьми битах,
  зато ни один сервер по дороге не превратит кириллицу в вопросительные
  знаки и не обрежет длинную строку. 8BITMIME и SMTPUTF8 не
  используются.
- **Дословные поля не чинятся.** Адрес, свой заголовок, дата
  и идентификатор с управляющим знаком — отказ, а не очистка; имя
  человека в строковом адресе и значение своего заголовка не кодируются.
  Кому нужно имя не из ASCII — пишет адрес таблицей. Так же отказом
  встречаются папка, имя и пароль ящика: литералов IMAP `{n}`, которые
  пронесли бы и перевод строки, пакет не шлёт, и папку с управляющим
  знаком в имени он не откроет.
- **Предел по умолчанию — 10 писем, свежие первыми.** Остальные ждут
  следующего раза; кто хочет всё, называет `limit` сам. Свежие — это
  письма с конца нумерации. У IMAP номера идут в порядке прихода
  по RFC 3501, а у POP3 порядка номеров RFC 1939 не задаёт, и его
  выбирает сервер. Сверено живыми серверами: Dovecot 2.4 и GreenMail 2.1
  нумеруют по приходу, и предел берёт последние письма. Mailpit 1.21
  показывает по POP3 лишь 100 последних писем и нумерует их от свежего
  к старому, так что предел меньше этой сотни забирает самые старые
  из неё. На таком сервере забирают всё окно — `limit = 100` — и ищут
  нужное письмо в нём: так делают живые проверки пакета на общем ящике
  стенда. По `Date` пакет письма не упорядочивает: чтобы узнать даты,
  пришлось бы прочесть заголовки всего ящика — ровно то, от чего бережёт
  предел, — а `Date` пишет отправитель, и одно письмо с датой из будущего
  перевернуло бы порядок и у сервера, который нумерует по приходу.
- **POP3 без UIDL.** Сервер без `UIDL` имён не даёт, и у писем нет `id`:
  по номерам между соединениями их не узнать.
- **Разбор до трёх уровней вложенности.** Глубже встречается разве что
  в письмах, пересланных пять раз подряд, а бесконечная рекурсия
  на кольцевой границе положила бы узел. Глубже третьего уровня часть
  остаётся сырой.
- **Вложения не перекодируются.** Файл — это байты: кодировку вложения
  видно в `charset` его части, переводить его — дело того, кто открывает.
- **Вход — только по паролю или токену.** POP3 — `USER` и `PASS` либо
  `AUTH XOAUTH2`, IMAP — `LOGIN` либо `AUTHENTICATE XOAUTH2`, без APOP
  и прочих механизмов SASL. CRAM-MD5 держится на MD5: пароля он
  не отдаёт, но содержимое письма без TLS видно всё равно.
- **Токен XOAUTH2 добывает поставщик вызывающего.** Пакет не ходит
  к службе OAuth 2.0 сам: поставщик — функция в `password`, и срок
  токена, его обновление и отзыв знает она. Токен, отозванный службой
  до срока, поставщик отдаёт до срока — и сервер отвечает отказом входа.

## Проверки

Проверки лежат в `test/` и идут на luatest. Протоколы почты — это
разговор, и проверяются они разговором: двойник соединения помнит, что
сказал пакет, и отдаёт то, что ответил бы сервер, а кончившиеся реплики
— молчание, обычный сценарий почты. Двойник сокета проверяет сам
транспорт; переход на шифрование подменяется целиком, и видно, что
сказано открытым текстом, а что — под шифрованием, и на каком
соединении прощались.

Двойники показывают, что мы правильно разговариваем сами с собой.
Настоящие серверы — что нас понимает кто-то ещё; разница вылезает
на первом же многострочном ответе. Живая проверка `mail_live_test.lua`
ходит на три сервера в докере, потому что ни один не умеет всего:

```sh
make mail-up      # Mailpit (SMTP 1025, POP3 1110, веб 8025), GreenMail (SMTP 3025, IMAP 3143),
                  # smtp4dev (SMTP 2025 со входом: CRAM-MD5, PLAIN, LOGIN, XOAUTH2; веб 2080)
make test
make mail-down
```

Без серверов живые проверки пропускаются: гейты не должны зависеть
от докера. Письма, ушедшие с узла, видно в веб-морде Mailpit —
[http://127.0.0.1:8025](http://127.0.0.1:8025); это же самый быстрый
способ посмотреть, что именно собрал пакет.

Ряды метрик (`series_test.lua`) проверяются на подменённом разговоре:
итог каждой отправки словом, отказ до сервера без длительности,
длительность по подменённым часам. Ряды читаются из реестра так же, как
их видит сборщик.

Письма приложения проверяются на настоящих шаблонах `tnt-template`
из исходников (`test/views`, письма-образцы `test/fixtures/letters.lua`),
а почта и очередь в процессе — двойниками договора. На временном узле
с настоящей `tnt-queue` (`letters_queue_test.lua`) очередь повторяет
отказ 451 тем же письмом с тем же `Message-ID` и зарывает 550
с первой попытки. Живая проверка `letters_live_test.lua` на Mailpit:
письмо, поставленное в очередь, пока почтовика не было, уходит после
повтора и приходит обеими частями из одного вида, а предпросмотр кладёт
в файл ровно ту разметку, какую получил ящик.

Покрытие строк — 100 %, убитых мутантов — 100 %.
